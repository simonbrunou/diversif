# Tests

How to run, write and triage this repo's tests. Commands live in `package.json`; this file holds what the scripts don't say.

## Running

- **`bun run test`**, with `bun run test <path>` for a focused run. It wraps `scripts/bun-test.ts`: paraglide compile, SvelteKit sync, then one `bun --conditions=browser test` process per file, so `mock.module` overrides stay inside their file. Bare `bun test` drops the browser condition, and every `@testing-library/svelte` component test fails with `` `mount(...)` is not available on the server ``: the command is wrong, not your change. A direct `bun --conditions=browser test <file>` skips the paraglide compile, so in a fresh worktree it fails with `Cannot find module '#lib/paraglide/runtime.js'` from `bunfig.preload.ts`: run `bun run paraglide` once (every `bun run test` does it first).
- **Coverage**: the 100% line gate runs only under `bun run test:coverage`, which is what CI runs.
- **Typecheck**: `bun run check` type-checks the shared helpers in `src/test/` along with the app. `tsconfig.json` still excludes the `*.test.ts` files, which hold hundreds of type errors (#554).
- **Dependency audit**: `scripts/audit-deps.sh` runs both `bun audit --audit-level=high` scopes of the CI job `Dependency vulnerability audit` with the job's own commands, or one scope with `production` or `all`. Run it when a brief asks for both audit scopes "as the CI job runs them".
- **Worktrees run through the dev shell.** `bun` is on PATH only inside the flake's dev shell, and a new worktree is not `direnv allow`ed, so prefix commands with `nix develop -c`. A fresh worktree needs `nix develop -c bun install --frozen-lockfile` first. Run `git push` that way too: the husky pre-push hook runs `bun run lint`, `bun run check` and CI's Fallow audit against `origin/main` (about 80 s) and fails outside the shell. On a branch stacked on another, push with `FALLOW_AUDIT_BASE=origin/<parent>`. It does not run the bundle budget: before you push a change that adds client code, run `bun run check:budget` (a full build, about 30 s). The pre-commit hook runs `npx lint-staged` under node and needs only `node_modules`.
- **The dev shell's Bun may lag the pinned one.** CI's `bun-version` inputs, `railpack.json` (production) and the `Dockerfile` pin one Bun, which Renovate's bun group moves and `scripts/check-bun-pins.sh` checks in the `Lint + typecheck` job. The dev shell takes `pkgs.bun` from nixpkgs through `flake.lock`, which Renovate does not update, so it runs whatever Bun nixpkgs shipped when the lock was last bumped: 1.4.2 on 2026-10-27, while the pins read 1.4.4. `scripts/check-bun-pins.sh` prints the pinned version and warns when the shell runs another. A result can depend on the version: Bun 1.4.4's coverage counts a default-parameter line that 1.4.2's does not (#528). To get CI's result locally, unzip the pinned release's `bun-linux-x64.zip` (GitHub releases, checked against its `SHASUMS256.txt`) into `/tmp/bun-pinned` and put the unzipped directory first on PATH inside the shell: `nix develop -c sh -c 'PATH=/tmp/bun-pinned/bun-linux-x64:$PATH; bun run test:coverage'`.
- **E2E from a worktree: give the run a free port.** Outside CI the Playwright `webServer` reuses any server already listening on its port, and the default 4173 is also where another worktree's E2E run or `bun run preview` serves its own build. Take 4000 plus the issue number (4452 for #452), check that `ss -ltn 'sport = :4452'` shows no listener, then run `nix develop -c env PORT=4452 bun run test:e2e e2e/offline.spec.ts`. The database file is already per worktree (`./e2e-test.db`, gitignored), and `test:e2e` resets it at the start of every run, so leave it in place afterwards.
- **Start an E2E job only when no other one runs or waits.** Until #478 gives E2E its own runner, two Playwright jobs on the shared runner can time each other out. Opening or reopening a PR starts an E2E job, and so do a push to an open PR's branch, a merge to `main` (its push run has one) and a rerun of the E2E job or of a whole run. A push to a branch with no PR starts none. Before each of them, run `scripts/wait-e2e-slot.sh` in one foreground shell call with a 10-minute timeout (Claude Code: `timeout: 600000`). Chain the command that starts the job with `&&`, as in `scripts/wait-e2e-slot.sh && nix develop -c git push`. A pipe through `tail` turns its busy exit 3 into success. It leaves out the run of your branch's pushed head (`origin/<current branch>`), which the next push cancels, and waits up to 7 minutes while another run's `End-to-end tests (Playwright)` job is `waiting` or `running`, printing each busy run. A clear check also claims the slot in a file the sessions on this host share, so a second session that cleared at the same poll waits for the first one's run. Exit 0 means clear, 3 still busy (run it again), 2 a missing or refused token or a wrong call. To rerun one job, take its id from `GET $API/actions/runs/<id>/jobs`, where `<id>` is the run's `id` field, not its run number. Then call `POST $API/actions/jobs/<job id>/rerun`. `$API` and the token come from `docs/agents/issue-tracker.md`. When the E2E job you wait for belongs to another agent session, message that session and take turns, each telling the other when its E2E job ends.

## Writing unit and component tests

- **Route pages mount like components.** Import the page dynamically, after every `mock.module(...)` call: `const { default: Page } = await import('./+page.svelte');`. A static import hoists above the mocks. Mock `$app/state` (a `page.url` getter), `$app/navigation`, `$app/env` and `svelte-sonner` (its dist can't load under `bun test`: it fails with `Cannot find package 'runed'`), and cast a minimal `PageData` with `as unknown as PageData`. Model: `src/routes/child/[id]/log/log.hint.test.ts`.
- **An enhanced form's result: keep the `enhance` callback.** The usual `$app/forms` mock (`src/test/app-stubs.ts` and the per-file copies) makes `enhance` a no-op, so only e2e sees what a page or a ConfirmModal does with an applied result. To test a dialog's result here, use `captureEnhance()` from `src/test/enhanced-submit.ts` (models: `submitDelete` in `src/routes/account/passkeys/page.svelte.test.ts`, `submitDialog` in `src/routes/child/[id]/settings/page.svelte.test.ts`):
  1. Before the dynamic page import, `const forms = captureEnhance(); mock.module('$app/forms', () => forms.module());`.
  2. `await forms.submit(open, result, update)`. `open` is the click that mounts the dialog's form: a ConfirmModal's form mounts only once its opener is clicked. The helper submits the last form that registered during `open`, so a page form that registered at mount is never the one submitted, and it throws when none did. `update` re-renders the page's `form` prop and stands in for SvelteKit; `trackSubmission` and ConfirmModal run for real. The helper awaits `tick()` before it returns.
- **A repas form's result: mock the durable submit.** The log and edit pages post through `RepasForm`, which sends the form with `submitRepas` (`src/lib/offline/submit.ts`) instead of `enhance`, and the `$app/forms` stub's `applyAction` does nothing, so the page's `form` prop never changes. To test what an edit page does with an answer (model: `src/routes/child/[id]/log/[entryId]/entry-edit.test.ts`):
  1. Before the dynamic page import, mock the submit to return a mutable answer: `mock.module('#lib/offline/submit.js', () => ({ submitRepas: async () => ({ kind: 'sent', result: answer }) }))`.
  2. Set `answer` to the `ActionResult`, then `fireEvent.submit` the form. The page receives it through RepasForm's `onapplied`.
  3. `waitFor` the change: the submit settles a few microtasks later.
- **Label tests: assert on `label.control`.** happy-dom pairs a field with every `label[for]` that names its `id`, so `getByLabelText` still finds a dialog's field when another field on the page has the same `id`. A browser points the label at the first field with that `id` in the page, and the dialog's field has no name (#468). `label.control` returns a single element for the `id`, so the assertion fails on the duplicate.
- **Server-rendered markup: prove it in e2e.** `svelte-loader.preload.ts` compiles every component with `generate: 'client'`, so a component test sees what the client renders and never the HTML the server sends. A Playwright test with JavaScript off (`openWithoutJavaScript` from `e2e/_helpers.ts`) sees only that HTML (model: `a refused login moves focus to the alert…` in `e2e/auth.spec.ts`). A component test can still stand in for the hydration render. `isHydrated()` from `#lib/boot-recovery.js` returns false until a test calls `markHydrated()`, just as it returns false while the client hydrates. A test that calls `markHydrated()` deletes `document.documentElement.dataset.hydrated` in `afterEach`, because the `afterEach` in `bunfig.preload.ts` empties only `document.body` (model: the `FormError focus` tests in `src/lib/components/ui/FormError.test.ts`, #469).
- **Focus checks: assert `document.activeElement`.** happy-dom sets no `autofocus` attribute on a `div` when Svelte sets the property, so assert where focus went, after `await tick()`. Svelte's autofocus moves focus only while the body has it, so a test asserting that an element leaves focus alone first puts focus on the body and asserts it. Compare `document.activeElement?.tagName` with `'BODY'`, because a failing `toBe(document.body)` prints happy-dom's whole window object.
- **Time-zone logic: pin `process.env.TZ`.** The dev host runs Paris time, so a host-local-time bug passes locally and fails only on a UTC server (#451). Set `process.env.TZ` in `beforeEach` (bun honours the change at run time) and restore it in `afterEach`, with `delete` when it was undefined. `describe.each` over zones runs every case once per host zone. Models: `src/lib/utils/dates.test.ts`, `src/routes/child/[id]/paris-midnight.test.ts`. Day logic lives in `src/lib/utils/civil-calendar.ts`; read its header.
- **Password hashes are cheap under `bun test`.** `bunfig.preload.ts` sets `__TEST_RELAXED_ARGON__`, so while `NODE_ENV` is `test`, `hashPassword` uses the E2E cost (`m=4096,t=1`) instead of the production `m=19456,t=2`. bun test sets `NODE_ENV=test` unless your shell already exports another value, which silently brings back the full cost. `Bun.password.verify` reads the cost from the stored hash, so verifying against those hashes is cheap too. The login decoy hash is built once per process, by the first unknown-address login, at the cost in force at that moment. Every Vite build inlines `false`. A test that needs the production cost stubs the global with `stubGlobal('__TEST_RELAXED_ARGON__', false)` from `src/test/bun-test-utils.ts`, and the preload's `afterEach` restores it. Model: the `hashPassword cost` block in `src/lib/server/auth.test.ts`.
- **An unhandled rejection fails the running test.** `bun test` fails whichever test is running when a promise rejection goes unhandled, even with a `process.on('unhandledRejection')` listener and even when the test body ends synchronously. A regression test for an "unhandled rejection" Sentry issue only has to drive the code path, with no listener or sleep.
- **A promise that can stay pending: `await p.catch((e: unknown) => e)`, then assert.** On bun 1.4.2 and 1.4.4 (checked 2026-10-27), `expect(p).rejects` and `expect(p).resolves` wait for `p` without letting the 5 s test timeout fire, so when `p` never settles the file spins at full CPU and never ends. A promise stays pending that way when an earlier failing test leaves module state stuck, such as the offline queue's `inFlight` (#452). Model: the `rejects and frees the lock when its pass throws` test in `src/lib/offline/queue.test.ts`.

## Writing E2E tests (Playwright)

- **An absent toast or a single message: take one count.** `toHaveCount(0)` retries for 5 s and svelte-sonner toasts expire after 4 s, so it waits a wrong toast out and passes (#437). Wait for the triggering work to finish (e.g. `expect.poll` on the queue), then assert `expect(await locator.count()).toBe(0)`, or `.toBe(1)` for a message that must show once. Watch the check go red before trusting it: against the old code, or, when the old code never shows the message, against a temporary mutation that shows it twice (a `toast()` next to the inline message). Models: the queue-replay test in `e2e/offline.spec.ts`, the counts in `e2e/account.spec.ts`.
- **Keep a user's JavaScript steps on the `page` fixture.** A context from `browser.newContext()` starts cold: it fetches every chunk again and installs the service worker, which precaches the whole app. In #501's first CI run, the `a refused save with JavaScript` tests, which each opened one, took 17 s to over 30 s, while the older `edit.spec.ts` tests on `page` took 9 s. That cost outweighs a branch on a `javaScript` flag in a parametrized test. Open a second context for the same user only to turn JavaScript off, with `openWithoutJavaScript` from `e2e/_helpers.ts`. A second user still needs a context of their own.
- **Budget a new test by its time in a busy CI run.** #501's edit tests took 2 s locally, 3 to 5 s on an idle CI runner, and 9 to 29 s when other jobs shared the runner. Read a new test's time in a run where other jobs shared the runner (`actions/tasks` shows them). When it exceeds 20 s there, or runs far slower than the older tests of its spec in the same log, give it `test.slow()` and a comment with the measured time, as the `auth routes` tests in `e2e/a11y-axe.spec.ts` do. Those three were one test until #477 split it by route group, so that each part gets its own 90 s budget.
- **Which project runs a spec.** In `playwright.config.ts` the `desktop` project runs every spec except those tagged `@mobile-only`, and the `mobile` project (an iPhone 14 viewport on Chromium) runs only specs tagged `@responsive` or `@mobile-only`. Tag a spec `@responsive` when it must also pass below the `md` breakpoint. A spec whose logic does not depend on the viewport needs no tag.
- **`ORIGIN` is read at build time.** adapter-node 6 has no runtime `ORIGIN`, so `vite.config.ts` pins `paths.origin` from `ORIGIN` during `bun run build`. A production build served over plain http without it fails every form POST with 403 "Cross-site POST form submissions are forbidden". The Playwright `webServer` builds with `ORIGIN=http://localhost:<port>`.

## Reproducing a bug on a production build

Dev mode registers no service worker and serves unbundled modules instead of the `/_app/immutable/` chunks, so chunk-load and service-worker failures show only on a production build. Reproduce them there, and rebuild and restart after every code change (a build takes about 30 s):

```sh
nix develop -c env ORIGIN=http://localhost:3123 bun run build
nix develop -c env DATABASE_PATH=/tmp/diversif-repro.db PORT=3123 WEBAUTHN_RP_ID=localhost NODE_ENV=production bun build/index.js
```

The browser Sentry SDK and the `/monitoring` tunnel start only when `PUBLIC_SENTRY_DSN` is set. It is read at run time, so for a browser Sentry repro add a fake one to the `bun build/index.js` line (for example `PUBLIC_SENTRY_DSN=https://0123456789abcdef0123456789abcdef@o1.ingest.de.sentry.io/2`), with `PUBLIC_SENTRY_TRACES_SAMPLE_RATE=0` and `PUBLIC_SENTRY_REPLAYS_ON_ERROR_SAMPLE_RATE=0` to keep traces and replays out of the envelopes. Leave `SENTRY_DSN` unset, and intercept `/monitoring` in the browser to read the envelopes: the tunnel would otherwise relay them to the DSN's host. Delete `/tmp/diversif-repro.db*` afterwards.

## Triaging a red run

- **Read the failing job's log first.** A status's `target_url` ends in `/actions/runs/<index>/jobs/<n>`. `GET $API/actions/runs?run_number=<index>` returns that one run with its `id`, and `GET $API/actions/runs/<id>/logs` returns a zip with one `<job name>-<job id>-attempt-<n>.log` per job, from its latest attempt only. After a rerun, `GET $API/actions/jobs/<job id>/logs?attempt=<n>` returns an earlier attempt's log as plain text. The web log URL answers 404 to a token. This Forgejo ignores `limit` unless `page` is also set.
- **E2E timeouts in the `a11y axe — auth routes` tests (`a11y-axe.spec.ts`, `walks the signed-in surface` before #477 split it), `cross-tenant-isolation.spec.ts`, `owner invites a co-parent…` (`membership.spec.ts`), `the password page says why a change was refused…` (`account.spec.ts`) and the older `edit.spec.ts` tests `edits a standalone repas…` and `edits a meal…`** (`Test timeout of 30000ms exceeded`, 90000ms for the a11y auth-route tests and those two edit tests) mean the runner was overloaded, until #478 moves E2E to its own runner. Confirm an overlap with `GET $API/actions/tasks?page=1&limit=50`: another `End-to-end tests (Playwright)` job whose `run_started_at` to `updated_at` span overlaps yours (yours has `run_number` equal to your run's index). Without such a job, the other jobs on the runner can still be the load: in run 253 the a11y walk took 1.2 min on the desktop project, against 13.7 s locally, while no other E2E job ran. Other repos share the runner too, and `GET https://git.sbrn.eu/api/v1/repos/simonbrunou/<repo>/actions/tasks?page=1&limit=50` lists a repo's jobs.
- **A timeout in a test your branch added** is that test's own cost when it runs far slower than the older tests of its spec in the same log. Read « Keep a user's JavaScript steps on the `page` fixture » and « Budget a new test by its time in a busy CI run ».
- **A timeout in `src/routes/login/page.server.test.ts` is not load noise.** Its rate-limit tests loop up to 21 logins each. At full Argon2 cost two of them crossed the 5 s per-test limit on a loaded runner (#475). `bun test` now hashes at the relaxed cost, and the file runs in under a second. A rerun alone passes only because the load is gone, so it hides a real regression. Look for a change that brings the full cost back: a `NODE_ENV` the CI job or your shell now exports, or a test that sets `NODE_ENV` to something other than `test`, or `__TEST_RELAXED_ARGON__` to `false`, around a loop or before the first unknown-address login.
- **`Bundle size budget` red with `Total JS too large`.** The job sums the JS files under `.svelte-kit/output/client/_app/immutable` against `maxTotalJsBytes` in `scripts/bundle-budget.json`, and the headroom shrinks between bumps: 927 bytes on 2026-10-25, which #513's 941 bytes crossed. When the growth is intentional, raise the limit in a commit that gives main's and the branch's measured totals and keeps about 6 KB of headroom, as 1d1ce24 does.
- **« Has been cancelled »**: a new push cancels the previous SHA's CI run (`cancel-in-progress` in `.forgejo/workflows/ci.yml`), and every status of the old run reads `failure` with that description. Not a test failure.
