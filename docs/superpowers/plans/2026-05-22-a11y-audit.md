# A11y audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add axe + Lighthouse e2e gates on every public + auth-required route, fix every violation surfaced, then lock the gates so a11y/best-practices/SEO regressions are caught at PR time.

**Architecture:** Two new Playwright specs — `e2e/a11y-axe.spec.ts` runs in the existing `desktop`/`mobile` projects (so axe covers both viewports), `e2e/a11y-lighthouse.spec.ts` runs in a NEW dedicated `lighthouse` project (workers:1, fixed CDP port). Phase 1 lands the infrastructure with soft gates (`expect.soft` for axe, score thresholds set to 0 for Lighthouse); Phase 2 fixes violations category-by-category and flips to hard gates in a single final commit.

**Tech Stack:** `@axe-core/playwright`, `playwright-lighthouse`, existing SvelteKit + Tailwind + bits-ui.

Create `e2e/a11y-axe.spec.ts`:

```ts
import { test, expect } from '@playwright/test';
import AxeBuilder from '@axe-core/playwright';
import { dismissWelcomeIfPresent, signUpAndCreateChild } from './_helpers';

/**
 * a11y axe sweep — runs WCAG 2.1 AA + best-practice rules against every
 * public and auth-required route. Tagged @responsive so both the desktop
 * and mobile Playwright projects pick it up; auth routes share one signup
 * per worker via test.step for speed.
 *
 * Phase 1 of Bundle C ships these as SOFT gates (`expect.soft`) so the
 * initial PR doesn't fail itself before the violations are triaged.
 * Phase 2 flips to hard `expect.toEqual([])` in the final commit.
 */

const TAGS = ['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'best-practice'];

interface AxeViolation {
  id: string;
  impact: string | null | undefined;
  description: string;
  nodes: { target: string[]; failureSummary?: string }[];
}

function formatViolations(violations: AxeViolation[]): string {
  if (violations.length === 0) return 'no violations';
  return violations
    .map((v) => {
      const nodes = v.nodes
        .slice(0, 3)
        .map((n) => `      ${n.target.join(' ')}\n      ${n.failureSummary ?? ''}`)
        .join('\n');
      const more = v.nodes.length > 3 ? `      (+${v.nodes.length - 3} more nodes)` : '';
      return `  [${v.impact ?? 'minor'}] ${v.id} — ${v.description}\n${nodes}${more ? '\n' + more : ''}`;
    })
    .join('\n');
}

async function axeSweep(page: import('@playwright/test').Page) {
  const result = await new AxeBuilder({ page }).withTags(TAGS).analyze();
  // Phase 1: soft assertion — failures are logged but don't fail the test.
  // Phase 2 will replace `expect.soft` with `expect` (hard).
  expect.soft(result.violations, formatViolations(result.violations)).toEqual([]);
}

const PUBLIC_ROUTES = [
  '/',
  '/signup',
  '/login',
  '/cgu',
  '/mentions-legales',
  '/politique-confidentialite',
  '/cookies',
  '/sources',
  '/offline'
];

for (const route of PUBLIC_ROUTES) {
  test(`a11y axe: ${route} @responsive`, async ({ page }) => {
    await page.goto(route);
    await axeSweep(page);
  });
}

test.describe('a11y axe — auth routes @responsive', () => {
  test('walks the signed-in surface', async ({ page }) => {
    const childId = await signUpAndCreateChild(page, 'A11y', '2025-08-01');
    await dismissWelcomeIfPresent(page);

    const routes = [
      '/account',
      '/account/profile',
      '/account/sessions',
      '/account/theme',
      '/account/delete',
      '/child/new',
      `/child/${childId}`,
      `/child/${childId}/foods`,
      `/child/${childId}/foods?segment=allergens`,
      `/child/${childId}/foods?segment=categories`,
      `/child/${childId}/foods?segment=bilan`,
      `/child/${childId}/guide`,
      `/child/${childId}/log`,
      `/child/${childId}/report`
    ];

    for (const r of routes) {
      await test.step(`axe ${r}`, async () => {
        await page.goto(r);
        await axeSweep(page);
      });
    }
  });
});
```

import { test } from '@playwright/test';
import { playAudit } from 'playwright-lighthouse';
import { dismissWelcomeIfPresent, signUpAndCreateChild } from './_helpers';

/**
 * Lighthouse audit sweep — runs in the dedicated `lighthouse` Playwright
 * project (workers:1, CDP port 9222). Same route set as a11y-axe.
 *
 * Phase 1 ships with thresholds set to 0 (soft — Lighthouse still
 * collects category scores and writes HTML reports, but the test passes
 * regardless). Phase 2's final commit raises the thresholds to:
 *   accessibility: 95, best-practices: 95, seo: 95, performance: 0
 * Performance stays at 0 — Bundle D will set the perf budget.
 */

const SOFT_THRESHOLDS = {
  accessibility: 0,
  'best-practices': 0,
  seo: 0,
  performance: 0
};

const REPORTS_DIR = 'lighthouse-reports';

async function lighthouseAudit(page: import('@playwright/test').Page, route: string) {
  await playAudit({
    page,
    thresholds: SOFT_THRESHOLDS,
    port: 9222,
    reports: {
      formats: { html: true, json: true },
      name: route.replace(/[^a-z0-9]+/gi, '_').replace(/^_|_$/g, '') || 'root',
      directory: REPORTS_DIR
    }
  });
}

const PUBLIC_ROUTES = [
  '/',
  '/signup',
  '/login',
  '/cgu',
  '/mentions-legales',
  '/politique-confidentialite',
  '/cookies',
  '/sources',
  '/offline'
];

for (const route of PUBLIC_ROUTES) {
  test(`lighthouse: ${route} @lighthouse`, async ({ page }) => {
    await page.goto(route);
    await lighthouseAudit(page, route);
  });
}

test.describe('lighthouse — auth routes @lighthouse', () => {
  test('walks the signed-in surface', async ({ page }) => {
    const childId = await signUpAndCreateChild(page, 'A11yLH', '2025-08-01');
    await dismissWelcomeIfPresent(page);

    const routes = [
      '/account',
      '/account/profile',
      '/account/sessions',
      '/account/theme',
      '/account/delete',
      '/child/new',
      `/child/${childId}`,
      `/child/${childId}/foods`,
      `/child/${childId}/foods?segment=allergens`,
      `/child/${childId}/foods?segment=categories`,
      `/child/${childId}/foods?segment=bilan`,
      `/child/${childId}/guide`,
      `/child/${childId}/log`,
      `/child/${childId}/report`
    ];

    for (const r of routes) {
      await test.step(`lighthouse ${r}`, async () => {
        await page.goto(r);
        await lighthouseAudit(page, r);
      });
    }
  });
});

## Phase 2 — Fix violations, harden the gate

### Task 7-N (one per violation category): Fix + commit

For EACH distinct rule category found in Task 6's triage, create ONE commit that fixes that category across all flagged routes.

**Recommended priority order:**

1. **`image-alt`** — every `<img>` needs `alt` (or `alt=""` for decorative). Usually a couple of components.
2. **`button-name` / `link-name`** — icon-only buttons missing `aria-label`. Often FAB, close buttons.
3. **`color-contrast`** — adjust Tailwind palette / opacity values. Touches `tailwind.config.js` + maybe a few component classes.
4. **`heading-order`** — wrap orphan `<h2>` in proper section semantics, or demote/promote.
5. **`label`** — form inputs missing associated `<label>` or `aria-labelledby`.
6. **`landmark-*`** — `<main>` / `<nav>` / `<aside>` coverage; usually a wrapper fix in the layout.
7. **`focus-visible` / `focusable-content`** — focus indicators after `outline-none` removal.
8. **`html-has-lang`, `document-title`, `meta-viewport`** — Lighthouse SEO/best-practices fixes; touch `app.html` or `+layout.svelte`.

**Per-category fix workflow (repeat for each):**

- [ ] Read the violation log entries for the category. Note the routes + DOM selectors flagged.
- [ ] Open one of the affected files. Fix the markup / styling / class. Make the change minimal — only address the flagged issue, not unrelated nits.
- [ ] Re-run JUST the axe spec to confirm the rule's violation count drops:
  ```bash
  E2E_DATABASE_URL=... npx playwright test --project=desktop e2e/a11y-axe.spec.ts -g "<route>" 2>&1 | grep -c '<rule-id>'
  ```
  Where `<rule-id>` is e.g. `color-contrast`. The count should drop monotonically as you address more nodes in the category. (Or, if you fixed the whole category in one shot, drop to 0.)
- [ ] Run `npm run check` after edits.
- [ ] Run `npm test` to make sure unit tests still pass (color-contrast changes might affect snapshot tests etc.).
- [ ] Commit:
  ```bash
  git add <files>
  git status  # only category-related files
  git commit -m "fix(a11y): <category short description>"
  ```

Examples of commit titles (only commit what's actually found):

- `fix(a11y): alt text on landing hero + child avatar images`
- `fix(a11y): aria-label on FAB + bento sheet close button + locale switcher`
- `fix(a11y): bump foreground/70 text on surface-2 to foreground/85 for 4.5:1`
- `fix(a11y): wrap orphan h2 in section landmarks across Discover bento`
- `fix(a11y): associate form labels in /signup, /login, /child/new, /child/[id]/log`
- `fix(a11y): add focus rings on icon-only buttons that lost outline in Bundle 1`

**Iteration check:**
After each category fix commit, run the FULL axe sweep + lighthouse sweep again (steps from Task 6) to confirm:

- The category's count drops (validates the fix).
- No NEW violations were introduced (validates no regression from the fix).
