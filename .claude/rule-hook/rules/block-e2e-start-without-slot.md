🚫 **This command can start a CI E2E job: put the slot check in front of it**

Opening a PR, merging one and rerunning the E2E job or a whole run each start an `End-to-end tests (Playwright)` job on the shared runner, and two side by side time each other out: on 2026-11-02 the #628 merge, made without the check, started run 430's E2E job beside run 428's. Run it as `scripts/wait-e2e-slot.sh && <command>`, with the timeout and the exit-3 retry that AGENTS.md « Before you start a CI E2E job » gives. When the command works on a branch other than the checked-out one, give the script a SHA as its argument: `scripts/wait-e2e-slot.sh <sha> && <command>`. That is the branch's pushed head, or for a rerun the run's `commit_sha`; testing.md « Start an E2E job only when no other one runs or waits » lists each case. The rule lets the slot check through only when `&&` follows the script name, at most one argument and any output redirects, such as `scripts/wait-e2e-slot.sh <sha> > /tmp/slot.out 2>&1 && <command>`. It reads output redirects there, after the argument, such as `>`, `>>`, `2>`, `&>`, `&>>`, `2>&1` and `>&2`. It never lets a pipe through. After `| tail -1`, `&&` reads the exit status of `tail`, not the script's, so the rule blocks it. It reads only these arguments: an unquoted word, such as a SHA, with no quote, `\`, `#`, `[`, backtick or parenthesis, other than the parentheses of a `$(…)` in it with no blank, quote, `\`, backtick, parenthesis, `#`, `<`, `[`, `&`, `;` or `|` inside; a `'…'`; a `"…"` with no `\`, `[` or backtick; a `"$(…)"` with no quote, `\`, backtick, parenthesis, `#`, `<` or `[` inside, and no `case` with a blank after it that starts the `$(…)` or follows a blank, `;`, `&`, `|`, `{` or `!`; and a `` "`…`" `` with no `"`, `\` or other backtick inside. Outside `'…'` and `` "`…`" ``, each `$` must start a plain variable, such as `$H`, `$1` or `${H}`, or one of the two `$(…)` forms. In every form, a `;`, a `||`, a lone `&` or a newline blocks: each ends the chain, as the next paragraph says. Any other argument blocks. For those arguments, put the SHA in a variable first: `H=$(git rev-parse origin/<branch>) && scripts/wait-e2e-slot.sh "$H" && <command>`.

The start command must follow the slot call through `&&` links only. A link may hold a pipe, as in `scripts/wait-e2e-slot.sh && git push 2>&1 | tail -3 && <command>`: the shell runs that pipeline only once the slot call succeeds. These end the chain: a `;`, a `||`, a lone `&` (one outside `&&`, `>&`, `&>` and `|&`), and a newline that ends a line with text on it, unless that line ends in `&&` or `|`, blanks after them allowed, or in a `\` right before the newline. So the rule blocks a start command after one of these, and one before the slot call. It also blocks a start command after a `||` before the slot call, as in `true || scripts/wait-e2e-slot.sh && <command>`, where `true` skips the slot call, unless a `;`, a lone `&` or a newline sits between that `||` and the slot call. It finds these characters wherever they sit, inside quotes and a `$(…)` too. So a loop or an `if` after the slot call blocks, and so does a `{ … }` group with a `;` or a newline before the start command, though the shell gates them: write a plain `&&` chain instead, such as `scripts/wait-e2e-slot.sh && T=$(…) && curl …`. A negated slot call, as in `! scripts/wait-e2e-slot.sh && <command>`, blocks too: the `!` turns the busy exit 3 into success.

The rule reads the command text only. When this command starts no E2E job (a rerun of another job, such as the unit job testing.md reruns after a runner cancel; a variable such as `$API` that points at another repo, since the rule reads a `$NAME`, a `$1` or a `${…}` with no blank or nested `${…}` inside, right before `/actions/…/rerun` or `/pulls/…/merge`, as diversif's API; a commit message, search or `--help` that quotes these words), add a `# no-e2e-job` comment to it. The comment turns the rule off for the whole call, an E2E start in it included: run a command that starts no E2E job, such as the unit job's rerun, in a call of its own with the comment, or after the slot call in its chain. `fj pr -C <clone> …` passes, so keep it for a PR in another repo's clone. A `git push` to an open PR's branch, a PR opened through `POST $API/pulls` and a reopen through the API also start an E2E job, and stay your call.
